## Notes

- **Pebble has no runtime text anti-aliasing.** `graphics_context_set_antialiased(ctx, true)` smooths only vector shapes (arcs, circles, round rects, paths, lines) — it never touches text, which is drawn from fixed bitmap fonts with no sub-pixel glyph rendering. The old codecorner "transparent text over a colour bitmap" trick is about compositing text with a transparent background over an image, not smoothing its edges; the reddit thread is the native AA-shapes API. So the way to make text read better on the watch is size, weight (fake bold by drawing twice 1px apart) and contrast (see `temp_ink`), not AA. Applies to every face in this repo. Established 2026-09-05 doing the Aura Weather craft pass.
- **A second concurrent `pebble` connection bumps the running app back to the launcher.** While an app is running on the emery emulator, opening a separate `pebble logs` / `pebble screenshot` / `pebble install` connection to capture or navigate can knock the app out to the launcher mid-session — which looked exactly like a "Details card crash" (empty fault logs, blank screen) during the Aura Weather pass but was a capture artifact, not a code bug. Capture strictly sequentially on one connection: use `pebble install --emulator emery --logs` (logs stream on the same connection that installs), page with `emu-button`, and never run a concurrent `pebble logs`/`screenshot` against the same live app. The deck was proven to render all cards 0-8 twice with no crash once capture was serialised. Diagnosed 2026-09-05.
- **CloudPebble auto-commits Settings edits back to GitHub, reformatting and possibly mutating `package.json` fields beyond what was edited.** Fixing the message-keys list through CloudPebble's Settings UI on 2026-09-04 triggered a background commit (`f6c2461`, "Message keys") that rewrote `package.json` in CloudPebble's own canonical style (alphabetized, 4-space indent) and, as a side effect, regenerated the app `uuid` and changed `name` from `aura-essential` to `aura-es` — neither of which the Settings edit had any business touching. A `uuid` mismatch against the published app is silent until publish/install time, where it would register as a new, unrelated app rather than update the existing listing. **After any CloudPebble Settings-page edit that causes an auto-commit, diff the resulting `package.json` against `main`'s for `uuid`/`name` drift before trusting the branch again** — don't assume only the edited field changed.
- CloudPebble's per-project **Settings > PebbleKit JS Message Keys** list is separate, manually-maintained metadata — it does **not** auto-sync from `package.json`'s `messageKeys` array on a GitHub pull, even when "last synced" shows a recent timestamp (that only reflects the source-file pull, not this list). If `messageKeys` ever changes in a face's `package.json`, that CloudPebble list needs a matching manual edit too, or the build fails with `MESSAGE_KEY_X undeclared` while local builds (which regenerate the header straight from `package.json`) keep succeeding. Discovered 2026-09-04 chasing the essential CloudPebble failure above; likely tripped by re-pointing/re-importing the `cloudpebble-essential` deploy branch that same day (`a6e7e18`, "build Emery only on this deploy branch"), which apparently picked up (or was cloned from) aura-analog's key list instead of essential's own.
- Dashboard/appstore listing icon = the **real Aura brand icon** downscaled, not a Pebble-specific redraw. Master at `docs/store/aura-brand-icon.png` (1024px, also served at askmira.es/aura/assets/icon.png); `scripts/make-app-icons.sh` Lanczos-downscales it to `app-icon-80.png` (Small) and `app-icon-144.png` (Large). Only used on the developer dashboard, so it does not need to match the Pebble launcher's tinting rules like `menu-icon.png` does. Don't redraw it.
- CloudPebble runs an older **pebble-tool (5.0.39)** than local (5.0.40), and the two disagree on message-key codegen: 5.0.40 emits `MESSAGE_KEY_*` as `extern uint32_t` globals defined in `message_keys.auto.c`; 5.0.39 emits `#define` macros with no globals. Always `#include "message_keys.auto.h"` in C (works with both); never hand-declare the keys `extern` (links locally, fails on CloudPebble with `undefined reference`). This is what broke the first CloudPebble build of essential.
- Store screenshots are now generated **without patching the source**: build+install once, then drive each theme with `pebble send-app-message --emulator emery --app-uuid <uuid> --int <key>=<val> ...` using the runtime message-key IDs (SLOT1..3 = 10000..10002, TOPCOLOR/BANDCOLOR/BOTCOLOR = 10003..10005, SEPCOLOR 10007, COMPCOLOR 10008, TIMECOLOR 10009, WX_TEMP/WX_CODE/WX_OK = 10015..10017). Inject demo data with `emu-steps 8432`, `emu-battery --percent 100`, `emu-heart-rate 68`, and set the calendar day via `emu-set-time <unix>` (compute the epoch against Europe/Madrid so the clock reads 10:09 despite CET/CEST). Heart-rate gotcha: set the HR **before** the redraw-triggering `emu-set-time` (with a short sleep) or the bpm label renders empty. This leaves the tracked source completely untouched — no restore step.
- After any store-shot run, `aura-essential/build/aura-essential.pbw` still holds the last demo *settings* in emulator persist, but the tracked source is clean; rebuild with `pebble build` for a shippable `.pbw`.
- The emery emulator mutes saturated hues in its display simulation (canonical orange renders as coral). A real Time 2 shows it closer to the true `GColorOrange`. Not a bug.
- Publishing path: `pebble publish` uploads to the appstore dashboard API at `https://appstore-api.repebble.com` (override with `--api-base` or `PEBBLE_APPSTORE_API_BASE`), authenticated with a Firebase ID token from `pebble login`. `pebble install --cloudpebble`/`--phone` use the CloudPebble relay to sideload to a real watch. Login status was logged out at the end of this session.
- Menu image: bundled as `IMG_MENU_ICON` in each face (not referenced in C, ~0.5KB) so CloudPebble's publish flow can select it; the alternative is uploading `docs/store/menu-icon.png` directly on the developer dashboard. Drawn white-on-transparent so the launcher tints it.
- CloudPebble + this monorepo: CloudPebble builds the project at the repo **root**, and this repo has none (three faces in subdirs, `aura-analog` sorts first). Build a specific face via its `cloudpebble-<face>` deploy branch (regenerate with `scripts/sync-cloudpebble.sh <face>`; it force-pushes the subtree split, which is expected because the branch is a mirror, not shared work), or import `<face>-<version>-cloudpebble.zip` (project at the zip root, built with `git archive HEAD:<face>`). Those `*-cloudpebble.zip` import artifacts are gitignored.
- **`pebble emu-button` takes an action then the button**, e.g. `pebble emu-button --emulator emery click down` (actions: `click`/`push`/`release`; buttons: `back`/`up`/`select`/`down`). Passing just the button (`emu-button ... down`) silently does nothing and the screen never changes — a useful tell when every paged screenshot comes out identical to the first. Also: `pebble logs --emulator emery` streams and blocks a script; drop it or background it, and `pkill -f "pebble logs"` to free a wedged run.
- **The emery emulator ignores `pebble emu-set-time` for an app's `time(NULL)`** — the watchapp renders against the real wall-clock instead, so setting the clock to force a day or night sky does not work (both come out identical). To capture day vs night deterministically, force the sun window relative to `now` in the render (sunrise = now - 5h / sunset = now + 5h for day; sunrise = now + 2h for night), not via `emu-set-time`. Also, a bare `emu-set-time` does not force a hero redraw; page a card away and back to re-run the draw. Found generating the Aura Weather listing screenshots on 2026-09-04.
- **`gpath_draw_filled` omits a polygon's left boundary column.** A filled `GPath` whose left edge sits at x=0 leaves column 0 unpainted while filling flush on the right. Fix by translating the path 1px left (`gpath_move_to(p, GPoint(-1, 0))`) so the left boundary moves off-screen; safe when the right edge is already a pixel past the screen (at `L + W`). This is what left the 1px strip down the Aura Weather hero scene.
- **Aura Weather provider strategy (decided 2026-09-04, in `aura-weather/docs/06-vision-and-roadmap.md`):** Open-Meteo is the worldwide default (free, no account) because the Spanish Pebble market is small and reach comes first; AEMET is the Spanish enrichment (free key). Open-Meteo has no prose bulletin and no warnings, so the phone generates its own plain-language summary + threshold advisories for everyone, overwritten by AEMET's official boletin + CAP aviso in Spain. Any source is acceptable as long as it is free, even if it needs a free key. MeteoAlarm (Europe) and weather.gov (US) are the free official-warning feeds to add later.
- Appstore version format: `docs/DISTRIBUTION.md`'s checklist wants `version` = `major.minor.0`. The SDK built and released `1.0.1` cleanly and it is fine as a GitHub release, but the Pebble store historically reads only major.minor, so confirm the live portal accepts a non-zero patch before publishing, else bump to `1.1.0`.
